# Changelog — ASW Training Record

_Append-only. Newest entries at the bottom._

## 2026-09-24
- Phase 1–3: Excel analysis, field mapping and database design (`docs/01_Excel_Analysis_Mapping_DB_Design.md`).
- Database: schema, triggers (audit log, stamping), analytic views, `rpc_dashboard`, `rpc_report`, `rpc_employee_target`, shared import engine (`import_training_rows`, `import_employees`, `import_expenses`) with dry-run preview, RLS for Admin / HR-Training / Viewer.
- Historical migration builder (`scripts/build_historical_seed.py`); verified on Postgres: session counts per year match the Excel dashboard (2566: 135, 2567: 122, 2568: 71, 2569: 60), 7,322 participants (3 true duplicates skipped, 1 row without year flagged invalid).
- Frontend (Vue 3 + Vite): Dashboard (Excel layout + hours/cost/expense/insights), Training Record, Training Session (create flow, participants, results, expenses), Participants, Calendar (month/week/day), Master Data (employee, course + analysis, category, type, trainer, provider, department, section, company, expense category, budget), Expense (all/food/other), Report Center (15 reports), Employee History, Monthly Management Report, Custom Report, Import Center, Export, Users, Roles, Audit Log, Settings.
- GitHub Pages deploy workflow.
- Historical import runner `scripts/run_historical_seed.mjs` (`npm run seed:run`, dev dependency `pg`): runs all seed chunks in one transaction, `--dry-run` rolls back, refuses to run on a non-empty database unless `--allow-existing`, verifies participants / sessions / employees / per-year counts against the Excel-derived seed rows. Tested on local Postgres (PGlite): 7,336 rows → 7,322 imported · 3 duplicate · 1 invalid (Teambuilding BU2) · 0 failed; re-run = all duplicates, no new rows. Import Center is not used for historical data (it does not read the "Training Courses" sheet and tags rows `Excel Import`).
- Go-live config: GitHub repository variables `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` (publishable key, no secret key anywhere), `feat/app` fast-forwarded into `main`, GitHub Pages deployed (https://prsnamnam-hub.github.io/training-record/). Supabase Auth Site URL set to the Pages URL; redirect allow-list: Pages URL `/**` and `http://localhost:5173/**`.
- System › Users: Admin can create users with a password (confirmed immediately, role chosen) and set a new password for any user, via Edge Function `supabase/functions/admin-users` (validates caller JWT + active Admin in `profiles`; service_role key stays server-side). No schema change — `admin` remains the top (superadmin) role.
- **Historical data imported into Supabase** (one transaction, verified in-database before commit): 7,336 rows → 7,322 participants imported · 3 duplicates skipped (logged `duplicate_in_file`) · 1 invalid (Teambuilding BU2, no year/date — not guessed) · 0 failed · 398 sessions · 967 employees · 308 courses. Staging schema dropped afterwards.
- Dashboard vs Excel (sheet Dashboard / Dashboard Data): yearly sessions 135/122/71/60, participants 2566–2568 (2,516/2,081/1,625), employees, ≥2-course target, % Inhouse, all 12 months of 2568 and training type split match exactly. 2569 participants 1,100 vs Excel 1,103 (the 3 duplicate rows Excel counts twice; target 310 vs 313 for the same reason). Department totals match (1,625); 59/71 department names match exactly — the rest differ only because departments with one code but several spellings are merged to the most frequent name (design decision). Training hours / cost: Excel has none, database 0 (no mock data).
- Performance fix (applied to Supabase with owner approval): RLS policies on business tables now call `(select public.can_view())` / `(select public.can_edit())` / `(select public.is_admin())` so the check runs once per query instead of once per row of every joined table; profiles policies unchanged. Before the fix `rpc_report` / `rpc_dashboard` timed out (>8 s) for signed-in users; after: full report + dashboard < 4 s. Permissions re-tested (admin/viewer/no-role, insert/update/self-update) — identical to before. Also ran `ANALYZE` after the bulk import (stale statistics made plans ~4× slower); runbook updated.

## 2026-09-25
- Navigation simplified: sidebar has 6 categories only (Dashboard, Training, Expense, Reports, Master Data, Settings) with no icons; each category's pages are tabs above the content (`src/lib/menu.js`). No page or feature removed — Export moved under Reports, Import Excel under Master Data; "System" renamed "Settings" (its settings page is now the "General" tab).
- Logo: official ASSET WISE logo (`public/logo-assetwise.png` navy for the login page, `logo-assetwise-white.png` for the dark sidebar — transparent PNGs made from the supplied logo).
- UI refresh (modern, user-friendly): light sidebar with the navy ASSET WISE logo and pill highlight, frosted sticky top bar with rounded search, segmented pill tabs for category pages and in-page tabs, 14px-radius cards with soft shadows, KPI cards with color dot + delta chips, roomier tables with uppercase headers, focus rings on inputs/buttons, softer modals/toasts, mobile sidebar backdrop. Font: IBM Plex Sans Thai + Inter (later replaced, see below). Chart palette switched to a validated colorblind-safe categorical order (dataviz reference palette). CSS only + small template tweaks; no feature or data change.
- Menu restructured to the owner's 5 sections: **Dashboard · Training Record · Database · Report · Settings** (`src/lib/menu.js`). Other pages kept as tabs (calendar, training history, expense, master data, other reports, export, audit log) — nothing removed.
- Training Record flow: **Part 1** one-page course form (course, รุ่นที่ → display name, date(s), location, trainer, Inhouse/Public/Online segmented choice, expense lines; extra fields collapsed) → save → **Part 2** on the session page: type an employee code (or paste many) → live preview of name / department / status from the employee master → Enter adds; unknown codes and duplicates are reported. Picker and Excel-by-code import remain as secondary options. Status defaults to Completed for past dates, Scheduled for future.
- Database: "นำเข้าพนักงาน (Excel)" page (Import Center preset to the employee import), employee list, courses, master-data page with entity chips, other imports.
- Report: รายงานหลักสูตร (`/reports/course`), รายงานรายบุคคล (employee history), รายงานฝ่าย (`/reports/department`); the full Report Center (+ monthly / custom) is "รายงานอื่น ๆ". Report definitions moved to `src/lib/reports.js`.
- Settings › Users: admins can delete a user (Edge Function `admin-users` action `delete`: soft-deletes the auth user so audit/created_by history stays valid, removes the profile; cannot delete yourself). Function v4 deployed via CLI (verify_jwt unchanged = true).
- Wording: "Part 1 / Part 2" removed from the course form and course page (stepper keeps plain step names).
- Expense entry simplified to 4 fields everywhere it is entered or listed: ประเภทค่าใช้จ่าย · จำนวน · ราคา/หน่วย · รวม (form lines, course expense tab + edit dialog, expense list). Existing description/vendor/meal data in the database is untouched, just not shown.
- UX: filter bars show the 3 main filters; the rest sit behind "ตัวกรองเพิ่มเติม" (badge = hidden active filters), "ล้างตัวกรอง" appears only when something is filtered. Page titles/labels now Thai and match the menu tabs; long technical subtitles shortened; breadcrumb labels removed where the tab bar already shows the location.
- Fonts: **Inter** for English and digits, **Noto Sans Thai** for Thai (font stack `Inter, 'Noto Sans Thai'` — Inter has no Thai glyphs so Thai falls through), charts use the same stack.
- Training Record: first tab renamed **บันทึกฝึกอบรม** and opens the entry form only (no list/filters). The course list moved into **ประวัติการฝึกอบรม** with a รายหลักสูตร / รายบุคคล switch (`HistorySwitch.vue`); course pages open from there (edit, add participants, expenses). Viewers (no edit right) land on the history tab.
- บันทึกฝึกอบรม: course name is a plain text field (no suggestion dropdown, browser autocomplete off); a typed name that matches an existing course is still linked to that course on save.
- Participants of a course now show: รหัส · ชื่อ · นามสกุล · ชื่อเล่น · ฝ่าย · ระดับตำแหน่ง · การเข้าร่วม (เข้าร่วม / ไม่ได้เข้าร่วม) · Pre-Test · Post-Test · Certificate (upload / view / replace). Attendance also sets completion (เข้าร่วม → Completed, ไม่ได้เข้าร่วม → Not Completed) so reports stay consistent.
- Migration **004** applied to Supabase: `training_participants.pre_test_score`, `post_test_score` (nullable, ≥ 0); private bucket `certificates` (PDF/PNG/JPG/WEBP ≤ 10 MB) with RLS — tested in a rolled-back transaction: admin can upload/read, a user without a role cannot upload or list. Files open through 2-minute signed URLs; path stored in `certificate_url`.
- Participant Excel upload rewritten: columns รหัสพนักงาน · การเข้าร่วม · Pre-Test · Post-Test (header names matched loosely; เข้าร่วม/ไม่ได้เข้าร่วม/Y/N accepted); new codes are added with those values, people already in the course are updated; unknown codes reported. "ดาวน์โหลดแบบฟอร์ม Excel" gives the template (pre-filled with the current list). Export uses the same columns.
- บันทึกฝึกอบรม: saving a course/รุ่น/date/type that already exists no longer shows the raw Postgres error (`training_sessions_natural_uq`); the form checks first and shows a Thai message with a "เปิดรายการเดิม" link. Tested: re-entering "test รุ่นที่ 1" 25 ก.ย. 2569 Online → message shown, nothing inserted.
